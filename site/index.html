  • a sandbox per agent — every agent runs as an unprivileged user in its own systemd sandbox or container, with memory, cpu and process limits. it writes to its workspace and nothing else. sandboxes →
  • a budget per agent — every model call goes through a metering gateway that prices it, enforces daily budgets, spots loops and stops the agent when the money runs out. api keys never enter the sandbox. gateway →
  • default-deny egress — only allowlisted domains resolve. agents reach model providers through the gateway, nowhere else.
  • evidence for everything — a hash-chained, signed audit log, signed provenance on agent commits, dlp on prompts, policy as code and four-eyes approval. audit →
  • never hunt for the stuck one — every pane says working, blocked or idle. when an agent waits for an answer, nestlo tells you, in the terminal or on your phone. tuios → · herdr →
  • vms for people and agents — nestlo cloud gives every user persistent vms with their own disks, a private https url, sharing, custom domains, and integrations that inject secrets at the network edge. cloud →
  • work, not just chat — an orchestrator, a scheduler, github triggers and a software factory turn issues into reviewed pull requests. factory →
  • runs what you already run — claude code, codex, gemini cli, cursor, opencode, aider, goose and the rest, pre-installed and pinned. nestlo doesn't wrap them; it fences them. agents →
  • one file, one rebuild — the whole machine is a nixos flake. roll forward, roll back, rebuild it bit for bit on another box.

install

$ git clone https://github.com/anubhavg-icpl/nestlo && cd nestlo
$ nix build .#vm-image
$ cp result/*.qcow2 nestlo.qcow2 && chmod u+w nestlo.qcow2
$ qemu-system-x86_64 -m 8192 -enable-kvm -bios OVMF.fd \
    -drive file=nestlo.qcow2,if=virtio
# the iso is signed and attached to every release
$ nix build .#iso-image
$ sudo dd if=result/iso/nestlo-*.iso of=/dev/sdX bs=4M status=progress
# boot the stick, then (erases the disk; only ssh keys can log in):
$ sudo nestlo-install /dev/nvme0n1 --ssh-key "ssh-ed25519 AAAA… you@laptop"
$ ssh admin@nestlo
$ nestlo workspace create api --from https://github.com/me/api.git
$ nestlo spawn claude --workspace api --budget 5
$ nestlo list          # agents, status, spend today
$ nestlo logs <id>     # every model call with tokens and cost
$ ssh lobby@cloud.example.com new --name web
$ ssh -t lobby@cloud.example.com ssh web    # a shell in the vm
$ open https://web.cloud.example.com/       # its private https url

needs nix with flakes, on x86_64-linux or aarch64-linux. then: nestlo spawn, walk away, nestlo list when you're back. quick start →

what's inside

run agents safely

  • 20 agents, pinned
  • sandboxes and containers
  • metering gateway: budgets, loops, routing, replay
  • local models, localai and vllm, gpu scheduling
  • openshell sandboxed runtime
  • runtime security (tetragon ebpf)
  • red-team, mcp scan, pr review

get work done

  • orchestrator and scheduler
  • github triggers: issue → pr
  • software factory
  • tuios and herdr workspaces
  • agent orca on k3s
  • a2a and acp
  • skill packs, 36 mcp servers, agentgateway, toolhive

run it like production

  • nestlo cloud: vms, https, teams
  • audit log and dlp
  • provenance, policy and rbac
  • spiffe identity and cedar, openbao
  • genai tracing, agent beacon
  • backups, alerts, runbooks
  • web dashboard
